Getting started

NoaCG Studio makes broadcast graphics — lower thirds, scoreboards, tickers, quiz boards, countdowns — in the browser, and gets them on air two ways: a live production you drive from an online dashboard, or an exported package that runs offline in whatever system your studio already uses.

  1. Open the studio. The creation wizard offers four doors: a template from the catalog, a description for AI, your own artwork, or a blank start.
  2. Style it — colors, typefaces, your logo, motion — beside a live preview. Every change writes real HTML/CSS/JS you can open, or never look at.
  3. Finish, then either export a package straight away or collect graphics into a production and run the show.

The guides below cover the parts people ask about: bringing your own design in as an SVG, connecting playout systems, live data, and letting a coding agent do the authoring.

Import your own SVG graphic

SVG import is the way to bring a graphic you designed yourself into NoaCG. Design it in Illustrator, Figma or Inkscape, export an SVG, and drop it on the Import door: your text layers become operator fields, and the pixel-exact graphic — your typography, your geometry, nothing redrawn — goes on air and exports to every target like any other graphic.

Where to drop it: the studio → New graphic → Import graphic.

The five rules that decide whether it works

  1. Give the file a size. A viewBox (or width+height) is required — it is the design space every field position is measured against. 1920×1080 with a transparent background is the predictable choice for frame-exact artwork; a smaller artboard imports as a free-floating object placed by the zone picker.
  2. Keep text as text. Every live <text> layer becomes an editable operator field, bound in place. Text converted to outlines cannot be edited in place — the import offers a fallback (a matching editable line placed over the measured outline), but the good road is re-exporting with real text.
  3. Name your layers. Layer names become the field labels an operator reads: "Home team" reads better than "Rectangle_3". No naming convention is required beyond that.
  4. Embed your pictures. A linked image is a network reference and is stripped on import — an exported graphic must play out with no internet.
  5. Do not animate in the design app. SVG-native (SMIL) animation is removed with a note. Motion is added in NoaCG's Animation step, where the timeline and the playout server can drive it deterministically.

When a typed value is longer than the design was drawn for, the generated code answers in one fixed order: fill the shape you drew the line in, grow the panel only if you opted in, wrap into the room the design already has, shrink to a readability floor, then warn the operator. The artwork is never reshaped behind your back and copy is never cut.

Fonts

An SVG names its fonts; if the playout machine lacks the family, the "exact" graphic silently isn't. The import inventories every family and, per family, matches a bundled face, offers the Google Fonts library (fetched at design time and embedded — exported code never reaches the network), or takes a font file you upload for a licensed face. An unresolved family warns and continues. PostScript names (Archivo-Bold) are understood.

Export settings, app by app

AppSettings that matter
IllustratorFile → Export → Export As… → SVG (not "Save As"). Font: SVG (not outlines) · Images: Embed · Object IDs: Layer Names · Minify: off. Name your layers first — duplicates are safe.
FigmaName the layers, select the frame, Export → SVG with Include "id" attribute ON and Outline text OFF.
InkscapeSave As… → Plain SVG. Label layers and objects. Do not run Object to Path on editable text, and do not use flowed text (drag-drawn text boxes) — it exports as <flowRoot>, which no browser renders.

Ready-made files to try — a lower third, a scorebug, an outlined-text example and an Illustrator-shaped export — are in the repository's docs/svg-samples folder.

A quiz board can carry its behaviour in the file too: draw the base look, then one hidden layer per moment (answer picked, right, wrong, locked in) and the import's behaviour pickers wire them up — see graphics with behaviour.

End credits

A credit roll is a list of people, and a list of people is not a list of fields. Every end-credits design has one field for the whole roll — a text box you paste into, in the studio, on the production dashboard, or later in whatever plays it out. A show with five camera operators does not add five fields to the template.

So the format has to carry the one distinction a credit roll is made of: which part is the role, and which part is the person. There is one mark to learn.

A colon ends a role. Everything else is a name.

Director: Alex Rivera

A role with more than one person puts the colon at the end of its own line, and the people follow beneath it — for as long as no new role appears: 

Camera Operators:
Jonas Berg
Lena Fors
Petri Salo

That is the whole idea: you type it the way you would write it on paper, instead of repeating the word Camera on five lines.

The complete set

  • Director: — a role; every line under it is one of its names.
  • Director: Alex Rivera — the same, inline, for a role with one person.
  • Director TAB Alex Rivera — the same. This is what a paste from a Google Doc table or a spreadsheet column looks like, so it just works.
  • Director | Alex Rivera — the same, with the original separator. Older lists keep working.
  • Alex Rivera — a name: it joins the role above it, or stands on its own if there is none.
  • # PRODUCTION — a department heading, above a run of roles.
  • A blank line starts a new section.

A semicolon works everywhere a colon does, because that is the mark some other template systems use.

Nothing is required. Paste a bare list with no marks at all and every line is read as a name — a clean column of names. And a heading is marked or it is not a heading, which is what lets a roll end on “Special thanks to everyone who made this show possible” without that sentence being set in accent capitals.

The same text in any design

The format says what the content is, never how it is arranged — so switching design never means retyping the credits. Classic Roll gives you centred blocks with the role over its names; Column Roll puts the role right-aligned in a left column with its names stacked in the right; Programme Roll sets it as serif leader rows on paper. Walls, donor boards, sponsor crawls and schedules in the same category read the same text.

Classic Roll adds one choice in the wizard's Style step — Emphasis. Role (the default) sets the role big and bold with its names quieter beneath it, which is what stays right when one role credits five people. Name sets the name big with the role as a small label above it: the film convention, and the better read when nearly every role has exactly one person.

Tickers

A ticker is a rundown of stories, and a rundown is not a list of fields. Every ticker design has one field for the whole rundown — a text box you type or paste into, in the studio, on the production dashboard, or later in whatever plays it out. Adding a story never adds a field.

So the format carries the one distinction a ticker item is made of: which part is the kicker — the tag a story is filed under — and which part is the story. It is the same shape as the credit roll above, on purpose.

A colon ends a kicker. Everything else is the story.

SPORT: United win 3-0

A desk with several stories puts the colon at the end of its own line, and the stories follow beneath it — until a blank line or the next kicker: 

SPORT:
United win 3-0
City held at home
Rovers sign a goalkeeper

The complete set

  • SPORT: United win 3-0 — one story, tagged SPORT.
  • SPORT: — a kicker; every line under it carries it.
  • SPORT TAB United win 3-0 — the same as the first, which is what a paste from a spreadsheet column gives you.
  • Storm warning issued — a plain story, with no tag at all.
  • A blank line closes the open kicker.

A semicolon works everywhere a colon does. And nothing is required: a rundown typed with no marks at all is a plain list of stories, exactly as tickers read before kickers existed.

Scores, clocks and links are safe

The colon has to be followed by a space, or end the line. That is what keeps a ticker's own numbers out of it: 

NORTHERN UNITED 2:1 CITY ROVERS
Polling stations close at 20:00
Full results at https://example.org

None of those is a kicker, and TRAVEL: the 20:45 service is cancelled is read the way you meant it. One more difference from end credits: a | is not a separator in a ticker, because Bilingual Crawl already splits an item at it into its two languages.

The same rundown in any design

The format says what the content is, never how it is arranged — so switching design never means retyping the rundown. Every ticker draws a kicker in the accent colour ahead of its story, and a design that wants it somewhere else places it itself: Status Rotator puts it in a fixed-width name column, which is what makes a service status scannable.

OBS, vMix & any browser source

A published production gives you one output URL — …/output?production=<slug> — that renders the whole show: transparent, all its graphics, driven live from the playout dashboard. Anything that can show a web page can carry it. Load it once, leave it up; graphics are cued by the operator, not by reloading the source.

Four rules apply to every browser-based playout:

  • Transparency is built in. Do not set a chroma key. A black or white box behind the graphic means the host is forcing an opaque background — check its custom-CSS / background settings.
  • Match the resolution exactly. Graphics are designed in real pixels (1920×1080 unless you chose otherwise). A mismatch does not crop — but it scales, and scaled text is softer than text rendered at its own size.
  • Resize the source, never the resulting layer.
  • Set the source's FPS to the channel's. Motion is authored in seconds and plays correctly at any rate, but a 30 fps source in a 50 Hz channel judders in a way that looks like the graphic's fault.

OBS Studio

  1. Sources → + → Browser.
  2. Paste the production's output URL (or, for an exported overlay, tick Local file and pick the .html).
  3. Set Width and Height to the graphic's own resolution, and FPS to your channel's.
  4. Leave the background alone — the page is already transparent.

Leave "Shutdown source when not visible" off for a production output: it tears the page down every time you hide the scene and forces a full rebuild on the way back.

An exported overlay package ships a local relay and launcher (Start controller.cmd on Windows, start-controller.command on macOS, ./start-controller.sh on Linux): it serves the folder locally, opens the operator page, and relays every command into the graphic — the route into a page loaded by OBS's or vMix's own browser engine. Fully offline, no installs.

vMix

  1. Add Input → More → Web Browser.
  2. URL: the output URL, or the full local path to an exported file.
  3. Set the width and height to the graphic's resolution.
  4. Use it as an overlay channel input.

When it does not work

CasparCG

CasparCG plays web pages through its HTML producer, so both routes work: the live output URL for a whole production, or an exported single-file template played from disk with no network at all.

Playing the production's output URL

CG 1-20 ADD 1 "https://noacg.studio/output?production=<slug>" 1
  • 1-20 is channel 1, layer 20 — use whatever your rundown expects.
  • The URL is a capability: anyone holding it can render the production (not operate it). Treat it like a password.
  • Load it once at the start and leave it up — graphics are cued from the dashboard, not by re-adding the layer.
  • Add &debug=1 while setting up for an on-screen status readout; take it off before air.
  • The page recovers by itself after a network drop or a layer restart, rebuilding what was on air without replaying animations.

Letting NoaCG load the layer for you

Instead of typing the command into the CasparCG Client, the production page can send it: Settings → Playout holds one server for the whole studio (host, AMCP port, channel, layer), and the production page grows a Put on air / Take off row. One thing must run on the machine you operate from, because a browser cannot open a raw TCP socket and AMCP is one: 

npx @noacg/cli caspar agent

Leave that terminal open. It prints an address and token to paste into the Playout settings, listens on 127.0.0.1 only, and CasparCG itself can be any machine on the studio LAN — exactly as with the Client. Test connection round-trips a real AMCP VERSION and shows the server's own version string. On the hosted studio, Chrome asks once whether the site may reach your local network — answer the prompt and it sticks. Safari refuses this outright; there, use the terminal route: 

npx @noacg/cli caspar play --url "https://noacg.studio/output?production=<slug>" --channel 1 --layer 20

What has been verified The output URL route has run on real hardware: a CasparCG 2.3.2 server rendered it at 1920×1080, transparent, surviving a renderer restart. The one-button connection is newer: its AMCP wire and every failure state are verified against protocol-accurate fakes and the test suite, but it has not yet driven a real CasparCG server. If it misbehaves on yours, the manual command above is the same live link — and we want to hear about it.

Playing an exported file

Export with the CasparCG target and you get one self-contained .html — fonts and images inlined, no network needed. Drop it into the server's template folder and drive it as a normal HTML template: 

CG 1-20 ADD 1 "<template-name>" 1 "<templateData>…</templateData>"
CG 1-20 PLAY
CG 1-20 NEXT
CG 1-20 STOP

A CasparCG client sends values by field id (f0, f1, …), so every exported package ships FIELDS.md: each field's id, name, type and default, with paste-ready payloads built from that graphic's own ids. Keep it open beside the client.

The playout dashboard

A production is the live unit: a pool of graphics, a cue rundown prepared in advance, and one persistent output URL. Each graphic is its own layer, so a bug, a lower third and a ticker can be on air at once. Publish the production and the dashboard drives it from anywhere — another tab, an OBS dock, a phone at the desk.

  • Preview and program. Two monitors and the verbs an operator actually uses: select a cue, check it on preview, Take. Staged edits air on an explicit take, never mid-keystroke.
  • Rehearse vs Show. Rehearse drives a local copy so you can walk the rundown without touching the air; Show drives the published output. The mode strip on the production page says which you are in.
  • Recovery is built in. Every command is a row in a durable log; the on-air renderer applies rows in order and, after a network drop or restart, catches up in order — rebuilding what was on air without replaying animations on screen.
  • Pictures without templates. "＋ Add pictures…" turns image files into cues — a holding slide, a sponsor card — aired like any other cue, one picture layer per production so stills replace rather than stack.

Audience join pages

A production can invite its audience in: a public join page at a readable URL (noacg.studio/join/<name> — the kind you read out on air) collects viewer messages and votes from any phone, no app and no account.

  • Nothing viewer-written airs on its own. Send-ins land in a moderation inbox; an operator picks what goes into the graphic. That separation is structural, not a setting.
  • Votes tally live into poll graphics — open the vote, close it, put the result on air when you are ready.
  • A presenter view (a separate link) shows the host what is coming without giving them operator controls.

Graphics with behaviour

A lower third plays and stops. A quiz board has to know which answer the contestant locked in and whether it has been revealed yet. NoaCG graphics can carry that logic themselves, as named states and real operator events — and the control panel is generated from them, so a move that would be wrong is greyed out instead of being wrong.

  • A quiz runs Select answer → Lock it in → Reveal — each a button on the dashboard, each legal only when the board's state allows it.
  • A scoreboard carries score up/down and clock start/stop as events; the numbers are data an operator or a feed writes.
  • Data never causes a state change. Updating a name or a score re-renders fields; states move only on operator events. That is what makes a feed safe to leave running.
  • Everything still degrades to plain stepping. Hand the same graphic to any playout system and it walks its steps in order like an ordinary template — the extra buttons are what you get when you drive it from NoaCG, never a reason it won't play elsewhere.

You can author behaviour without code: an imported SVG quiz board is just layers — draw each moment (answer picked, right, wrong, locked in), hide those layers in the design app, and the import wires them to the quiz behaviour. See the SVG guide.

Live data

Three doors, from no-setup to fully automated. All of them respect the same rule: data updates change what a graphic shows, never what state it is in — and the operator always wins, because their command lands later in the same log.

Type it on the dashboard

Every field is editable live from the production page: edit, stage, take. For most shows this is the whole answer.

A Google Sheet (or any published CSV)

Point a graphic at a published sheet and its fields follow the sheet — from anywhere, by anyone you share the sheet with. In the sheet: File → Share → Publish to web → CSV; in the studio, add the live-data source and paste the link. The generated polling code is ordinary, commented JavaScript appended to the graphic's own code (column headers map to field titles), so it runs wherever the graphic runs — the preview, an OBS browser source, an exported package — and you can open and edit the mapping like anything else.

The Production Data API

For a timing system, a results service or your own scripts: push values into a published production over plain HTTPS, authenticated by the production's own data key (minted when it is published). Writes become rows in the production's command log — the renderer cannot tell your update from an operator's, which is the point. 

curl -s https://noacg.studio/api/data/update \
  -H "Authorization: Bearer $NOACG_DATA_KEY" \
  -H "Content-Type: application/json" \
  -d '{"graphic": "House Scorebug", "values": {"Score A": 2, "Clock": "43:12"}}'
  • Fields are addressed by the labels the graphic shows its operator ("Score A"), so a feed and a spreadsheet speak the same language.
  • The key can write data only — it cannot play, stop, take or clear anything. A feed that could clear the frame would be a second operator with no face.
  • PATCH /api/data/patch goes one step further: write to a data path (match.home.score) and every graphic bound to it follows, without the feed knowing the rundown.
  • A worked example ships in the repository: a weather mini-pack driven by a small Node connector polling Open-Meteo — see DATA_API.md for the full reference, limits and error shapes.

Make graphics with Claude Code, Codex or any coding agent

Coding agents are good at writing HTML graphics. NoaCG gives them the missing half: a contract for what a broadcast graphic must expose, a validator that actually runs it in a live playout bench, and a door into your library. The agent designs the way it works best; NoaCG makes the result editable, controllable and playable — the same gate the studio itself uses.

The bridge is the noacg CLI, published on npm as @noacg/cli. You need Node.js and a system Chrome or Edge (the CLI drives the validator in a headless browser). No account is needed until you want to save into a library.

The loop

Ask your agent for a graphic ("make me a clean scoreboard for a floorball stream — home, away, period, clock"), or walk it yourself:

# 1. Start from a working chassis (optional — agents may also author from scratch):
npx @noacg/cli scaffold --type scoreboard --design neutral --out my-scorebug

# 2. Author: edit the package's HTML/CSS/JS the way you normally work.

# 3. Validate — the studio's own gate plus a live playout bench, with screenshots
#    (off-air, on-air, stress) so the agent can SEE what it made:
npx @noacg/cli validate my-scorebug --screenshots shots

# 4. Put it in your NoaCG library (login once; the key can only create graphics):
npx @noacg/cli login
npx @noacg/cli save my-scorebug

validate reports findings the way a compiler reports errors, and the agent iterates until clean; save refuses anything that does not pass. The saved graphic opens in your library like any other: editable in the studio, exportable to every target, ready for a production.

The package on disk is simultaneously a valid SPX package and an EBU OGraf v1 graphic — zip it and it also imports through the studio's Import door, or plays in any OGraf renderer. The full reference is AGENT_CLI.md.
